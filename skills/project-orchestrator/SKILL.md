# Project Orchestrator

## Required context
Read `../../knowledge/project-context.md`, `../../knowledge/knowledge-sources.md`, `../../knowledge/phase-skill-map.md`, `../../knowledge/requirements-index.md` and `../../knowledge/decision-log.md` before acting.

## Instructions
Read the knowledge files above, then identify the development phase and invoke the matching domain skills. For ambiguous work, use Superpowers brainstorming first. Produce a small implementation plan, list dependencies and acceptance gates, then delegate bounded tasks. Never implement across multiple phases without confirming prior gates from repository evidence. Do not proceed on work blocked by an open decision; name the OD ID instead. End by invoking verification-before-completion and summarising evidence, risks and traceability updates.

## Required output
- Decisions and assumptions
- Files/components changed
- Tests or verification evidence
- Risks and rollback notes
- Requirement IDs affected
